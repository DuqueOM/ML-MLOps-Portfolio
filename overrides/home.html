BankChurn Predictor

81% of requests failing. The model was fine.

A load test showed an 81% error rate on the BankChurn API. I found the root cause: uvicorn --workers inside Kubernetes — several workers competing for one shared CPU budget produce thrashing, not parallelism. I redesigned the inference path with asyncio plus a ThreadPoolExecutor (GIL analysis documented): errors dropped to zero and the CPU request was halved.

ChicagoTaxi Pipeline

The leak I found — and the honest score that was higher

Demand forecasting over 6.3M Chicago taxi trips. The first model used same-period averages (fare, distance, speed) that are only known after the fact: data leakage. I replaced them with lag features from past hours and a strictly temporal split, and R² went from 0.905 to 0.965 with features that exist at prediction time.
